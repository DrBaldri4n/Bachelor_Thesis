\subsection{Data Sources for Electric Vehicle Supply Equipment Anomaly Detection}
\label{subsec:data_sources_for_evse_anomaly_detection}

In line with the approach described in the paper \cite{EV_Security} "Enhancing EV Charging Station Security Using A Multi-dimensional Dataset : CICEVSE2024", Hardware Performance Counter (HPC) kernel events and tracepoint events were recorded to classify anomalies in Electric Vehicle Supply Equipment (EVSE) data. For efficient monitoring, the \texttt{perf} tool was utilized, a robust Linux performance analysis utility capable of capturing a variety of performance data, including hardware events, software events, and tracepoints \cite{perf_wiki}. This tool offers flexible and effective monitoring of system performance and is instrumental in diagnosing issues efficiently.\\
\\
To perform the data acquisition on a Raspberry Pi Zero W, the \texttt{perf\_exporter}\cite{perf_exporter} was used to record up to 900 tracepoint events, which were selected based on the CICEVSE2024 dataset. Initially, a Python script was developed to capture kernel and HPC events. When expanding to about 110 events, the runtime of the developed script increased to approximately 9 seconds, which proved insufficient for real-time analysis. Consequently, the internal workings of the \texttt{perf} tool were investigated to understand how it manages specialized events and optimizes recording.\\
\\
As detailed in "Linux \texttt{perf} event Features and Overhead" \cite{perf_event_overhead}, \texttt{perf} supports multiplexing, allowing the measurement of more events than there are available hardware counters, though the cost of accuracy loss and increased system overhead. Recent updates can result in resource usage exceeding 20\%, compared to approximately 2\% in older tool versions \cite{perf_event_overhead}. To minimize these inaccuracies, events were grouped per CPU, exploiting up to 8 available counter registers and limiting each group to a maximum of 6 events. \\
\\
For the monitoring interval, recommendations from the literature \cite{perf_event_multiplexing} addressing multiplexing and accuracy trade-offs were followed. The suggested minimum monitoring interval is around 10 ms for reliable results. Balancing the number of counter registers and striving for good measurement accuracy, groups of 6 hardware events per group were configured, with a monitoring interval of 0.1 seconds. This configuration yielded data with sufficient accuracy to detect anomalies in the EVSE dataset \cite{perf_event_multiplexing}.\\
\\
To further optimize efficiency and accuracy, the data acquisition script was re-implemented in Go. The Go programming language offers low-level hardware access and, with available libraries, integrates more seamlessly with the \texttt{perf} tool compared to Python.\\
Additionally, the script exports all monitored hardware events from \texttt{perf} into a Prometheus database, enabling centralized and convenient access to all collected data. This setup streamlines subsequent analysis, visualization, and anomaly detection activities.\\
\\
Instead of including the full script, its functionality can be summarized as follows. The script collects system performance metrics using the Linux \texttt{perf} tool and filters the relevant events specified in a YAML configuration file. It then formats these metrics in a way that is compatible with Prometheus and makes them available through an HTTP metrics endpoint.
