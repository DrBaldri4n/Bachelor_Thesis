\subsection{Parameter Configuration and Hyperparameter Optimization}
In this chapter, a closer look is taken at the chosen structure of the LSTM architecture and it is explained.\\

First, the training and test datasets are loaded, and the necessary configurations for features and labels are prepared. This ensures that the datasets are consistently structured before being passed into the model, with a clear separation between feature values and corresponding labels.\\

In the next step, the data is preprocessed. The class labels are converted from strings (``benign'', attack) into binary values (0 and 1). In addition, all feature values are standardized using the \texttt{StandardScaler}. This scaling step is crucial for training an LSTM model effectively. Unscaled data can lead to numerical instability and poor convergence in neural networks. LSTMs are particularly sensitive to the scale of input features because they use sigmoid activation functions, which operate best when input values are within a small, centered range. If the features have very different magnitudes, such as bytes transmitted (e.g., in thousands) versus CPU usage (e.g., in fractions), the model may focus disproportionately on features with larger numeric ranges, leading to biased learning and suboptimal performance \cite{input_scaling_important}. By standardizing the input features (i.e., transforming them to have zero mean and unit variance), it is ensured that the LSTM model can learn temporal dependencies more effectively and converge faster during training.\\

Since LSTMs are specifically designed to recognize temporal patterns, the dataset is further transformed into time sequences. A sliding window is applied over the data to generate fixed-length sequences. Importantly, only those sequences are retained in which all labels within the window are identical, meaning that the entire sequence is consistently classified as either benign or attack. This avoids ambiguous targets and ensures that the model learns clear and consistent classification patterns.\\

The model itself is designed as a stacked LSTM architecture. The first LSTM layer returns full sequences, allowing a second LSTM layer to process temporal dependencies at a deeper level. After each LSTM layer, dropout regularization is applied to improve the model’s ability to generalize. The final output layer uses a sigmoid activation function to generate the probability of a sample belonging to either the benign or attack class. This design provides a balanced trade-off between complexity and interpretability, making it well-suited for binary time-series classification tasks.\\

The training process is then carried out on the prepared sequences. The model is trained for 20 epochs, with a batch size of 32 samples. The batch size does not directly influence the final outcome of the model but impacts training efficiency and resource usage. Smaller batch sizes can produce noisier gradient updates, which may sometimes help generalization, while larger batches result in smoother updates at the cost of increased memory consumption. A batch size of 32 is a common compromise between these extremes \cite{batch_size_lstm}.\\

In addition, it should be noted that an early stopping function could be used instead of training for a fixed number of 20 epochs. Early stopping monitors the validation performance and automatically stops training when no further improvements are observed, thereby saving computation time and preventing overfitting. However, to keep the implementation simple, this additional feature is not discussed in detail in this work.\\
