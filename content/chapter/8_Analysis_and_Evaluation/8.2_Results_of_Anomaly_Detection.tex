\subsection{Results of Anomaly Detection Using the Machine Learning Model}

Up to this point, a good understanding of the data and the features relevant for the detection of attacks has been established as well as the configuration of the LSTM model has been obtained. Now a closer look is taken at the results of the anomaly detection using the presented LSTM model on the CEVSE2024 dataset and the dataset recorded for this work.\\

The model shows high accuracy (0.88) on the self-collected dataset, with strong performance in identifying benign cases (Class 0). In direct comparison, the results on the CEVSE2024 dataset are significantly stronger than those obtained on the self-collected dataset. The LSTM model achieves an overall accuracy of 0.99 with nearly perfect precision, recall, and F1-scores for both benign and attack classes. In contrast, the results on the self-collected dataset show lower precision and recall values for attack detection, which reduces the macro average and weighted average metrics.\\

As already observed during the exploratory data analysis, a central reason for these differences lies in the characteristics of the attack traces themselves. In the self-collected dataset, the peaks of scanning attacks such as OS-Fingerprinting, Portscans, and Aggressive-Scans are barely distinguishable from benign traffic. In the CEVSE2024 dataset, however, these attacks produce clearly visible deviations in the selected features, which allows the LSTM model to separate them more reliably from benign cases.\\

Potential reasons for these discrepancies are not related to hardware, since the experimental setup was reproduced one-to-one. More plausible explanations include background processes that cannot be controlled to exactly the same degree, or differences in the tools and parameter settings used to perform the scans. These factors can lead to stronger variations in the selected features and thus improve the separability of attack traffic. \\

It is important to note that the LSTM model was not altered between the experiments. The same architecture and hyperparameters were applied to both datasets, and the same feature set was used, namely the features identified during feature selection with the Decision-Tree-Classifier on the self-collected dataset.\\

These results are consistent and remain unchanged when analyzing the confusion matrix and the direct detection of attacks. After testing and analyzing with the monitored system, this work also includes testing the LSTM model in a live system. This is important to ensure that the model can detect attacks even if the data do not have the same timestamps, and to observe what happens if the environment is overloaded so that new data do not arrive at the same intervals as the training data when the processor is under heavy load.\\

At first, it was necessary to store the LSTM model as a .keras file and also save the scaler as a .pkl file. This makes it possible to scale all live data in the same way as the training data.\\

The system continuously collects live performance metrics from a monitored environment, which is only possible through collection with the \texttt{perf} tool and processing in the Prometheus database. Some metrics require the calculation of differences between successive measurements to reflect true activity changes and avoid permanent accumulation, as this can cause problems with the LSTM model if a counter is reset unexpectedly.\\

The collected data are normalized using a pre-trained scaler and then fed into a pre-trained LSTM model to predict whether the system is under attack or operating normally. The results, including probabilities for both benign and attack states, are logged into a \texttt{CSV} file for further analysis, while real-time feedback is printed to the console. This approach allows monitoring and detecting anomalies in a live environment, closely simulating conditions that differ from the controlled training setup.\\

After live testing the system for about six hours and 25 attacks, the following results are shown in figure \ref{fig:live_data_classification_results}:
\begin{figure}[H]
  \centering
  \includegraphics[width=1\textwidth]{pics/live_data_classification_results.png}
  \caption{Live data classification results}
  \label{fig:live_data_classification_results}
\end{figure}

It can be observed that the equal attack probability was about 20\% and reached the highest peaks during the flooding attacks, in the best case approaching almost 100\% attack probability. Additionally, during the time sequence when the Portscan attacks occurred, the attack probability increased significantly, leading to a clear rise. As expected, before the scanning attacks, OS-Fingerprinting and Aggressive-Scans showed only small peaks, as did the Slowloris attack.\\
